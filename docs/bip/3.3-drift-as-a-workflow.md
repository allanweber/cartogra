## LinkedIn Post (~300 words)

Most tools treat dependency drift as an alert: "service A is calling service B, which isn't in the catalog." It fires, someone mutes it, and the catalog stays wrong.

We built drift in Cartogra as a workflow instead. Every drift record comes with a decision, and every decision changes the catalog.

- **Undeclared** (traffic shows a call nobody declared) → **Accept**, which declares the dependency in one step.
- **Missing** (declared, but no traffic for a week) → **Remove declared**, which deletes the stale entry.
- Either → **Dismiss**, for "we know, and it's fine."

Three details turned out to matter more than the detection itself:

1. **Dismiss is permanent.** A dismissed drift is never raised again. A question re-asked every five minutes gets muted, and then the real ones get muted with it.
2. **Drift closes itself** when the condition clears: someone declares the edge elsewhere, or the call stops. Nobody has to clean up after the world fixes itself.
3. **The record never lies.** If you accept a drift but the observed call expired in the meantime, the action is rejected instead of being logged as accepted with nothing declared.

In the UI, opening a service's Drift tab shows only the drifts touching that service. During an incident, the tenant-wide backlog is noise; your service's two open questions are not.

Detection is the easy part. The hard part is making the right action the cheapest one.
