## Feature Summary

The Catalog screens are the operational heart of Cartogra. `/catalog` is a dense table of all registered services, used primarily during incident triage to locate ownership and health status quickly. `/catalog/$serviceId` is the service profile: a tabbed view of ownership, dependencies, contracts, and sync history. Together they answer the two most common questions: "what service is this?" and "who owns it?"

**Primary user action (Catalog list):** Scan the service list, apply a filter or search, find the affected service, and click through to its detail page — in under 10 seconds.
**Primary user action (Catalog detail):** Read ownership, health, and recent events from the Overview tab; navigate to Dependencies or Contracts tabs for deeper context.

---

## Design Direction

From **PRODUCT.md**: Decision-first over dashboard-first; evidence before opinion; operational speed with calm control; ownership clarity as a feature.
From **DESIGN.md**: Modern DevTool aesthetic — precision of Linear, airy typographic restraint of Vercel. "Quiet intelligence" using generous whitespace to reduce cognitive load while maintaining professional data density.

- **Color strategy:** Restrained. Health status badges provide all meaningful color. Purple accent (`primary: #6b38d4`) only on focus rings and active filter chips. All surfaces use DESIGN.md surface layering.
- **Scene sentence:** A platform engineer at midday tracking down who owns a failing endpoint, scanning the catalog list with one eye on Slack, wanting to click the right row within three seconds of landing on the page.
- **Anchor references:** Linear (issues list density and row interaction), GitHub (icon columns, clean table structure), PagerDuty (service directory, health-status-first layout).
- **Theme:** Light mode (scene sentence forces it — midday, incident context, daylight).
- **Anti-goals:** No card grid for the service list; no nested cards; no hero-metric panels; no decorative visuals.

## Layout Strategy

**Catalog list** sits inside `AppLayout`. No card wrapper around the table — rows extend full page width within the standard `24px` margin gutters (`spacing.margin` from DESIGN.md). The AppLayout header slot carries "Catalog" as the title and an "Add service" button in the actions slot. The filter bar lives directly below the header, above the table.

**Catalog detail** uses the same `AppLayout` shell. The page header shows the service name as the title with the health badge in the eyebrow slot. "Sync now" lives in the actions slot. Tab bar (Overview, Dependencies, Contracts, History) sits below the header, with tab content below.

## Screen: Catalog List (`/catalog`)

### Components

**Filter bar** (above table, full width):
- Search input: left-aligned, placeholder "Search services…", Lucide `Search` icon inside input left edge, `rounded-lg`, `border-default` border
- Filter chips (right of search, wrapping on narrow viewports): Team, Health, Tech Stack, SCM Provider — each a dropdown trigger button, `rounded-full`, shows `(N)` count badge when active
- Active chip fill: `primary-fixed` background, `on-primary-fixed` text
- "Clear all" text link appears at far right when any filter is active

**Table** (TanStack Table):

| Column | Width | Content |
|---|---|---|
| Service name | flex grow | Text link to `/catalog/$serviceId`, `500` weight, `primary` on hover |
| Team/owner | 160px | Team name, `on-surface-variant` |
| Health | 120px | Badge: Healthy / Warning / Critical / Orphan |
| Tech stack | 160px | Pill chips; max 2 shown, `+N more` overflow text |
| Last synced | 120px | Relative time; ISO tooltip on hover |
| SCM provider | 48px | 16px icon (GitHub / Azure DevOps icon), `on-surface-variant` |

- Column header row: `label` size, `on-surface-variant` text, hover reveals `ArrowUpDown` (Lucide) sort icon
- Active sort column: `ArrowUp` or `ArrowDown`, `on-surface` color
- Row dividers: `border-default` 1px bottom border

### States

| State | Behavior |
|---|---|
| Default | Full table, all columns populated |
| Loading | 5 skeleton rows matching column layout (shadcn `Skeleton`) |
| Empty — no services | Centered in table area: icon, "No services registered yet.", "Connect an SCM provider to start syncing services.", "Connect SCM" button → `/settings/connections` |
| Filtered to zero | "No services match your filters." + "Clear filters" link |
| Error | shadcn `Alert` (`error-container` bg): message + `(trace: {traceId})` in `mono body-sm` |

## Interaction Model

**Catalog list:**
- Click row → navigate to `/catalog/$serviceId` (full row is clickable, not just the name link)
- Row hover: background transitions to `surface-container-low`
- Search: debounced 200ms, TanStack Table `globalFilter` on service name
- Filter chips: dropdown select per chip; selecting a value activates the chip fill; multiple values per chip use OR logic within that filter
- Column sort: TanStack Table `getSortedRowModel`; header click toggles asc/desc/none

**Catalog detail:**
- Tab switching: TanStack Router search params (`?tab=overview`) to preserve tab on reload
- "Sync now" action: Lucide `Loader2` spinner during call; success refreshes "Last synced" timestamp inline (no page reload)
