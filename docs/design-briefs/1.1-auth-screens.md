## Feature Summary

The auth screens are the entry point into Cartogra for all users: initial account creation (3-step flow), return sign-in, email OTP verification, OAuth handoff, and password reset. They serve engineers and technical leads who have been invited to or are self-onboarding into a team's service registry. These screens must project professional calm — secure, fast, and unobtrusive — without any product-marketing energy.

**Primary user action (Login):** Sign in as quickly as possible and reach the Catalog.
**Primary user action (Register):** Create an account, verify the email address, and name the workspace — three discrete, linear steps.

---

## Design Direction

From **PRODUCT.md**: Brand personality is insightful, decisive, uncompromising. Tone is clear and direct. Auth screens are not a marketing surface — they are a gateway to a technical tool.
From **DESIGN.md**: Modern DevTool aesthetic. "Quiet intelligence." Soft Tech shape language. Inter typography throughout.

- **Color strategy:** Restrained. Purple (`primary: #6b38d4` from DESIGN.md) appears only on the primary CTA button and focus rings. All surfaces use DESIGN.md white/near-white surface tokens.
- **Scene sentence:** An engineer clicking a team invite link mid-morning at their desk — purposeful, in good light, wanting zero friction between the email and the catalog.
- **Anchor references:** Linear (auth flow layout and form precision), Vercel (minimal branded header, typographic restraint), Planetscale (clean devtool sign-in with OAuth-first layout).
- **Theme:** Light mode only (scene sentence forces it).
- **Anti-goals:** No dark backgrounds; no SaaS-hero/landing feel; no gradients; no illustration panels, split-screen imagery, or decorative art.

## Layout Strategy

All screens share a single layout shell:

- **Header:** Slim fixed top bar (`h-14`), Cartogra wordmark left-aligned, no navigation items.
- **Body:** Full-height centered column; form card sits at vertical-center with slight upward bias (~40% from top).
- **Form card:** `max-w-[400px]` width, `rounded-2xl`, `elevation-1` border, `p-8`, white background.
- **Footer:** Fixed bottom bar with Privacy and Terms links, `on-surface-variant` text, `body-sm` size.

Visual hierarchy inside each card: screen title (h2, 600 weight) → supporting sentence (body, `on-surface-variant`) → OAuth buttons → divider → form fields → primary CTA → secondary link.

## Screen: Login

### Layout

OAuth buttons above the divider; email form below. Screen title: "Welcome back." Supporting text: "Sign in to your workspace."

### Components

- Two full-width OAuth buttons: "Continue with Google" / "Continue with GitHub" (official brand icons, `rounded-lg`, `elevation-1` border, white background)
- "or continue with email" divider (sentence case, `on-surface-variant`, centered text)
- Email input (`type="email"`, label: "Email address")
- Password input with visibility toggle (Lucide `Eye`/`EyeOff` icon, right-aligned inside input)
- Primary CTA: "Sign in" (`primary` bg, `rounded-lg`, full width)
- "Forgot password?" link (below CTA, `on-surface-variant`)
- "Don't have an account? Register" link (below forgot, center-aligned)

### States

| State | Behavior |
|---|---|
| Default | All fields empty; Sign in button disabled |
| Field focused | Input border transitions to `primary`; 3px outer ring |
| Loading | Button spinner, inputs disabled |
| Invalid credentials | Inline alert below form: "Email or password is incorrect." No traceId (known client error) |
| Unverified email | Inline alert: "Please verify your email. [Resend verification email]" — link triggers resend API call |
| Server error | Alert: "{message} (trace: {traceId})" — traceId in `mono` font, `body-sm` size |

### Data Requirements

- `POST /auth/login` → JWT cookie set by gateway
- `POST /auth/resend-verification` → triggers re-send for unverified users

## Screen: Register — Step 1 (Account)

### Layout

Step indicator (1 of 3) at top of card. Title: "Create your account." No supporting sentence needed — the step indicator provides context.

### Components

- Step indicator: three dots or a "1 / 3" label in `on-surface-variant`; decorative only, not clickable
- OAuth buttons (same as Login — "Continue with Google" / "Continue with GitHub")
- "or continue with email" divider
- Full name input (`type="text"`, label: "Full name")

### States

| State | Behavior |
|---|---|

| Blur validation | Per-field inline errors on blur only |

| Submitting | Button spinner, all inputs disabled |
| Server error | Alert with traceId |

### Data Requirements

- `POST /auth/register` with `{name, email, password}` → sends OTP email, returns session token for step 2

## Screen: Register — Step 2 (Verify Email)

### Layout

Step indicator (2 of 3). Title: "Check your email." Supporting text: "Enter the 6-digit code we sent to {masked email}." Email masked as `al***@gmail.com`.

### Components

- 6 individual digit input cells (`type="text"`, `maxlength="1"`, `inputmode="numeric"`, `rounded-lg`, monospace font, `w-10 h-12`, centered digit)
- Countdown label: "Resend in {N}s" → transitions to "Resend code" button when timer reaches 0
- Auto-submit fires on 6th digit entered

### States

| State | Behavior |
|---|---|
| Default | First cell auto-focused; countdown starts at 60s |
| Typing | Auto-advances focus cell by cell; backspace moves back |
| Paste | Distributes pasted digits across all 6 cells |
| Resend active (60s elapsed) | "Resend code" button enabled; click resets countdown, sends new OTP |
| Invalid code | Cells shake (CSS transform, no bounce); error below: "That code isn't right. Try again." Cells cleared and re-focused. |
| Expired (10 min) | Error: "This code has expired." + active resend button shown immediately |
| Success | Auto-advances to step 3 — no manual confirm button |

### Data Requirements

- `POST /auth/verify-email` with `{code}` → advances registration session
- `POST /auth/resend-verification` → resets OTP, restarts server-side expiry

## Screen: OAuth Callback

### Layout

Full-viewport centered layout (no card). Header bar still visible. No footer needed.

### Components

- Lucide `Loader2` spinner (animated, `text-primary`)
- Caption: "Completing sign-in…" (`on-surface-variant`, `body`)

### States

| State | Behavior |
|---|---|
| Loading | Spinner + caption; this is the only default state |
| Success | Silent redirect to `/catalog` — user never sees a success screen |
| Error | Spinner replaced by an error card: provider name, "Something went wrong during sign-in.", "Try again" button (returns to `/login`), traceId in `mono body-sm` |

### Data Requirements

- Gateway handles `GET /auth/callback` (OAuth exchange); frontend only reads redirect result
- Error information carried in URL params or session; frontend reads and renders

## Interaction Model

- **OTP input:** 6 individual `<input>` cells. Typing auto-advances focus. Backspace on empty cell moves focus back. Paste distributes digits. Auto-submits on 6th fill.
- **Form validation:** On-blur per field for format/length; server errors inline on submit.
- **Primary button disabled:** Until all required fields non-empty. No eager validation.
- **Password visibility:** Lucide `Eye`/`EyeOff` toggle inside right edge of input.
- **Step progression:** Forward only; no back navigation on step 2 or 3. Step indicator is decorative, not interactive.
- **OAuth flow:** Click → provider redirect → `/auth/callback` loading → redirect to `/catalog` or error card.
