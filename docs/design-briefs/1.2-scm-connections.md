## Feature Summary

The SCM Connections screen (`/settings/connections`) is a settings screen where platform engineers connect GitHub and Azure DevOps to their Cartogra workspace. It is visited once during initial setup and rarely thereafter, except when rotating credentials or troubleshooting sync failures. It must be calm, precise, and focused — a one-task screen, not a dashboard.

**Primary user action:** Connect a provider (GitHub via OAuth or Azure DevOps via PAT) and confirm the connection is active before navigating away.

---

## Design Direction

From **PRODUCT.md**: Ownership clarity as a feature; workflow-native integration. Auth decisions made here affect all service sync and catalog visibility.
From **DESIGN.md**: Modern DevTool aesthetic; "Soft Tech" shape language; professional-grade reliability. "Quiet intelligence."

- **Color strategy:** Restrained. Status badges provide the only meaningful color. No accent surfaces.
- **Scene sentence:** A platform engineer at their desk on a Monday morning, setting up Cartogra's GitHub integration for their team's org — deliberate, focused, one task to complete before standup.
- **Anchor references:** Vercel (integrations/connections settings page), Linear (settings list items, clean form expand pattern), Doppler (provider connection with credential input inline).
- **Theme:** Light mode (deliberate setup task, daytime, scene forces it).
- **Anti-goals:** No card grid for the providers; no modal for revoke confirmation; no decorative provider hero artwork.

---

## Scope

- **Fidelity:** Production-ready — feeds directly into `/impeccable craft`.
- **Breadth:** One screen — `/settings/connections` — with two provider rows (GitHub, Azure DevOps) and their inline states.
- **Phase 1 constraint:** One connection per provider. Multi-org support deferred.
- **Interactivity:** Full spec (OAuth redirect, inline PAT form expand, inline revoke confirmation, error states).
- **Time intent:** Ship quality.

## Screen States

### GitHub Provider Row

| State | What user sees |
| --- | --- |
| Not connected | "Not connected" badge (`surface-container` bg), "Connect GitHub" button |
| Redirecting | Button shows `Loader2` spinner, disabled; tab navigates to GitHub OAuth |
| OAuth callback — success | Row: "Connected" badge (`success-container`), org name in `body-sm`, last-sync timestamp, "Revoke" button. No toast; the badge is the confirmation. |
| OAuth callback — error | `Alert` (`error-container`) below the row: provider error message + `(trace: {traceId})` + "Try again" link |
| Revoke pending | Action area shows `warning-container` background: "Revoke access?" label (`warning`, `label` size), "Yes, revoke" button (ghost with `error` text/border), "Cancel" link |
| Revoke in-progress | "Yes, revoke" button shows spinner |
| Revoked | Row returns to "Not connected" state |

### Azure DevOps Provider Row

| State | What user sees |
| --- | --- |
| Not connected | "Not connected" badge, "Connect Azure DevOps" button |
| Expanded (PAT form) | Row expands below header row; `surface-container-low` background; Organization URL input, PAT input (masked, visibility toggle), helper text for required scopes with external link, "Save connection" button (`primary`), "Cancel" link |
| Saving / testing | "Save connection" spinner; inputs disabled; "Testing connection…" caption below button |
| Test passed | Row collapses; "Connected" badge + org URL shown in `mono body-sm`, last-sync timestamp, "Revoke" button |
| Test failed | `Alert` (`error-container`) inline below form stays open: "Could not connect. Check your token and organization URL." + `(trace: {traceId})`. Form stays open for editing. |
| Revoke pending | Same inline confirmation as GitHub row |
| Revoked | Row returns to "Not connected" state |

### OAuth Callback Routing

The gateway's `/auth/callback` route (or a dedicated `/settings/connections/callback`) redirects to `/settings/connections?status=connected&provider=github` on success. The frontend reads the `status` param, shows the Connected state for the relevant provider, and immediately removes the param from the URL via `router.replace`.

## Interaction Model

- **GitHub "Connect GitHub":** Button click → same-tab navigate to GitHub OAuth authorization URL → callback → redirect to `/settings/connections?status=connected&provider=github` → frontend renders Connected state, clears URL params.
- **Azure DevOps "Connect Azure DevOps":** Button click → row expands inline (CSS `max-height` transition, ease-out-quart, ~200ms). Organization URL input receives auto-focus.
- **PAT input:** `type="password"`. Lucide `Eye`/`EyeOff` toggle inside right edge. Value is never shown in cleartext after save — displayed as masked dots if the row is somehow re-opened (but in Phase 1, the row collapses after save and only Revoke is available).
- **Revoke inline confirmation:** "Revoke" click → action area transitions (ease-out-quart) to `warning-container` tint with confirm UI. "Cancel" restores original row without API call. "Yes, revoke" calls revoke API; button shows spinner; on success row returns to Not connected.
- **Row expand transition:** `max-height` CSS transition from `0` to the form's natural height. Never animate height directly. Use `overflow-hidden` + transition to avoid layout jank.

## Open Questions

1. **Settings sidebar badge:** Should "Connections" show a provider count badge in the sidebar nav ("Connections · 1/2") to surface connection status without visiting the page?
2. **"Update token" action:** When Azure DevOps is connected, should there be an "Update token" action for credential rotation (re-expands the form without revoking), in addition to "Revoke"?
3. **Auto-sync on connect:** Does a successful connection immediately trigger an initial ingestion sync, or does the user initiate sync manually from the catalog?
4. **Multi-org forward compatibility:** The one-per-provider row layout is a single row. When Phase N adds multi-org support, the row becomes an expandable group with sub-rows. Design the row container to be composable for this — note in implementation.
