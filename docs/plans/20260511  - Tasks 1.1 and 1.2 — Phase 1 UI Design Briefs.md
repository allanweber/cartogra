# Plan: Tasks 1.1 and 1.2 — Phase 1 UI Design Briefs

## Context

Tasks 1.1 and 1.2 are the first Phase 1 items. They produce **confirmed design briefs** for all Phase 1 screens before any implementation begins. No auth UI or catalog UI code should be written until these briefs are confirmed. The brief sessions use the `/shape` skill, which interviews against `DESIGN.md` and `PRODUCT.md` to emit a structured design document.

---

## GitHub Workflow

1. Create one GitHub issue: `US1.1-1.2 — Phase 1 UI design briefs (auth + catalog + SCM screens)` — milestone `Phase 1 — Gateway MVP auth + Registry`
2. Branch: `feat/1.1-1.2-phase1-design-briefs` from `main`
3. All brief files committed to this branch; PR references the issue

---

## Session Order and Scope

### Session A — `/shape login`
Covers: **Login**, **Register**, **Forgot Password**, **Verify Email (OTP)**, **OAuth callback**

Key questions the brief must resolve:
- Email/password fields, OAuth buttons (Google, GitHub) layout on Login
- Register multi-step vs single page; required fields (name, email, password, tenant name)
- Forgot password flow: email input → confirmation message → reset link email
- Verify email: OTP code entry, resend timer, expiry messaging
- OAuth callback: loading/success/error states, redirect target
- Cookie-only auth (no localStorage); error state with `traceId` surfacing
- Mobile responsiveness; WCAG AA contrast on form fields

Output file: `docs/design-briefs/1.1-auth-screens.md`

### Session B — `/shape register`
Extends Session A for any Register-specific UX that warrants a separate pass (multi-step onboarding, team/tenant setup). If `/shape register` produces no new decisions beyond Session A, note that in the brief file and close the session.

Output file: merged into `docs/design-briefs/1.1-auth-screens.md` or a standalone `docs/design-briefs/1.1-register-detail.md` if meaningfully different.

### Session C — `/shape catalog home`
Covers: **Catalog list**, **Catalog detail**

Key questions the brief must resolve:
- Catalog list: filter bar (team, health, tech stack, SCM provider, search), row vs card layout, health badge design, orphan highlighting style
- Catalog detail: sections (overview, ownership, dependencies, contracts, health history), tab vs scroll layout
- Empty state (no services registered yet), loading skeletons
- Pagination or infinite scroll strategy
- How `traceId` appears in error states

Output file: `docs/design-briefs/1.2-catalog-screens.md`

### Session D — `/shape scm connections`
Covers: **SCM connections** (`/settings/connections`)

Key questions the brief must resolve:
- Connection list: GitHub and Azure DevOps cards, connection status, last-sync time
- Add connection flow: OAuth redirect (GitHub) vs PAT input (Azure DevOps)
- Revoke/reconnect flows, error and success states
- Where this screen lives in navigation (Settings vs sidebar item)

Output file: `docs/design-briefs/1.2-scm-connections.md`

```markdown
### Data Requirements
### Open Questions / Deferred Decisions
```
