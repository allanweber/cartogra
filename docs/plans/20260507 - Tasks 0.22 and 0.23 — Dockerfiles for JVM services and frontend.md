## JVM Dockerfile pattern (gateway / registry / ingestion)

Rules from `infra.md` that apply:
- Builder: `eclipse-temurin:25-jdk-jammy` / Runtime: `eclipse-temurin:25-jre-jammy`
- Layer order: base → OS deps → create user → build descriptors → fetch deps → source → build → runtime COPY → USER / ENTRYPOINT
- Non-root: `RUN useradd -m -u 1000 appuser` → `USER appuser`
- `ENV JAVA_OPTS="-XX:MaxRAMPercentage=75"` (never hard-set -Xmx/-Xms)
- ENTRYPOINT `["sh", "-c", "exec java ${JAVA_OPTS} -jar app.jar"]` for signal passthrough
- COPY only, never ADD
- `HEALTHCHECK CMD curl -f http://localhost:{port}/actuator/health/live || exit 1`
- Never tag `latest`

### Build strategy

All three services are part of the Gradle multi-module build. The builder stage must include the
full monorepo source (shared modules are compile-time dependencies). Use task-level targeting
(`./gradlew :services:{name}:bootJar`) to avoid building all services in a single image build.

Dependency-caching layer: copy all `build.gradle.kts` and `settings.gradle.kts` files first, run
the dependencies task, THEN copy full source. This keeps the layer cache warm when only source
changes.

### JAR artifact path

Each service produces a fat JAR at:
`services/{name}/build/libs/{name}-0.1.0-SNAPSHOT.jar`

Use a wildcard glob `{name}-*-SNAPSHOT.jar` to be robust against version bumps.

### Service-specific differences

| Service  | Port | Health path                          |
|----------|------|--------------------------------------|
| gateway  | 8080 | /actuator/health/live                |
| registry | 8081 | /actuator/health/live                |
| ingestion| 8085 | /actuator/health/live                |

### Dockerfile template (filled per service)

```dockerfile
# ── Builder ──────────────────────────────────────────────────────────────────
FROM eclipse-temurin:25-jdk-jammy AS builder
WORKDIR /workspace

# Gradle wrapper
COPY gradlew .
COPY gradle/ gradle/
COPY gradle.properties .
COPY settings.gradle.kts .
COPY build.gradle.kts .

# Build descriptors for all modules needed by this service
COPY shared/common/build.gradle.kts       shared/common/
COPY shared/contracts/build.gradle.kts    shared/contracts/
COPY shared/test-support/build.gradle.kts shared/test-support/
COPY services/{name}/build.gradle.kts     services/{name}/

RUN chmod +x gradlew

# Warm the dependency cache before copying source
RUN ./gradlew :services:{name}:dependencies --no-daemon --quiet

# Full source needed for compilation
COPY shared/   shared/
COPY services/{name}/ services/{name}/

RUN ./gradlew :services:{name}:bootJar --no-daemon -x test

# ── Runtime ───────────────────────────────────────────────────────────────────
FROM eclipse-temurin:25-jre-jammy AS runtime

RUN apt-get update \
 && apt-get install -y --no-install-recommends curl \
 && rm -rf /var/lib/apt/lists/*

RUN useradd -m -u 1000 appuser
WORKDIR /app

COPY --from=builder /workspace/services/{name}/build/libs/{name}-*-SNAPSHOT.jar app.jar

ENV JAVA_OPTS="-XX:MaxRAMPercentage=75"

USER appuser

EXPOSE {port}

HEALTHCHECK --interval=30s --timeout=5s --start-period=60s --retries=3 \
  CMD curl -f http://localhost:{port}/actuator/health/live || exit 1

ENTRYPOINT ["sh", "-c", "exec java ${JAVA_OPTS} -jar app.jar"]
```

## Frontend Dockerfile (stub — task 0.23)

TanStack Start (Nitro) is a **full-stack SSR** app, not a static SPA. The `.output/` dir produced
by `pnpm build` contains a Node.js server bundle at `.output/server/index.mjs`. Two decisions must
be settled in Phase 1 before this image is production-ready:

1. `VITE_API_BASE_URL` is baked in at build time (Vite convention). Phase 1 must decide between
   build-args-at-CI-time vs a runtime config injection approach.
2. TLS termination / static-asset serving strategy (Node serves everything vs nginx proxy).

The stub captures the build pattern and exposes these TODOs explicitly.

```dockerfile
# Phase 0 stub — see docs/execution-checklist.md 0.23 for deferral rationale.
# Two decisions required before this image is production-ready (Phase 1):
#   1. VITE_API_BASE_URL is baked at build time; decide: build-arg-per-env or runtime injection.
#   2. Static asset serving strategy: Nitro serves all vs nginx reverse proxy.

# ── Builder ───────────────────────────────────────────────────────────────────
FROM node:22-slim AS builder
WORKDIR /app

RUN npm install -g pnpm@10

COPY frontend/package.json frontend/pnpm-lock.yaml ./
RUN pnpm install --frozen-lockfile

COPY frontend/ .

ARG VITE_API_BASE_URL=http://localhost:8080
ENV VITE_API_BASE_URL=$VITE_API_BASE_URL

RUN pnpm build

# ── Runtime ───────────────────────────────────────────────────────────────────
FROM node:22-slim AS runtime

RUN useradd -m -u 1000 appuser
WORKDIR /app

COPY --from=builder /app/.output .output

USER appuser

EXPOSE 3000

# TODO Phase 1: add HEALTHCHECK once a /health or /api/health endpoint exists

CMD ["node", ".output/server/index.mjs"]
```

## Verification

After implementation, the following must pass:

1. **Build each JVM Dockerfile** from the repo root:
   ```
   docker build -f infra/docker/gateway/Dockerfile -t cartogra/gateway:local .
   docker build -f infra/docker/registry/Dockerfile -t cartogra/registry:local .
   docker build -f infra/docker/ingestion/Dockerfile -t cartogra/ingestion:local .
   ```
2. **Run `/check-docker`** on each Dockerfile to audit against project rules.
3. **Smoke-test a container** (optional at Phase 0): `docker run --rm -p 8080:8080 cartogra/gateway:local`
   and confirm `http://localhost:8080/actuator/health/live` returns `{"status":"UP"}`.
4. **Frontend stub**: `docker build -f infra/docker/frontend/Dockerfile -t cartogra/frontend:local .`
   must succeed (or fail only on a documented known issue logged as a TODO).
5. **Run `./gradlew build`** to confirm no regressions in the normal non-Docker flow.
